# Factory Tools — iPhone, Apple Watch, and iPad tools

An iPhone-first SwiftUI app using Apple's SwiftData. Its model container explicitly disables CloudKit. The Xcode project has no package dependencies, internet API, external network service, or paid-service integration; iPad commands use a direct local Network.framework connection.

The home layout adapts from one column on narrow screens to two columns on typical iPhones and three or four columns on wider layouts, keeping the card model independent of the device width. Small and medium cards share rows; large cards take a full row and show the progress details. Counter controls preserve 44-point action widths in the minimum-width two-column cards. At accessibility Dynamic Type sizes, cards get a wider minimum column so counters remain readable. The tool picker groups tools by the selected language's category and searches Japanese and English names and category labels regardless of the selected display language, as well as stable tool IDs. It stays open as tools are added, shows which tools are already on the selected home, and marks each preset complete once all its tools are present.

Phase 1 ships an iPhone app target plus the local `FactoryToolsCore` static framework. Core is linked by the iPhone and Watch apps and the test targets, and contains reusable, locale-neutral values and calculations. The localized Registry, input parsing, SwiftData models, and canonical `CounterService` stay in the iPhone app. Core includes iOS, iOS Simulator, macOS, and watchOS build settings.

The first launch creates a default home and settings record, selecting the default home. The home menu switches between saved home profiles, creates a named home, or opens home management to rename, select, reorder, and delete profiles. Deletion requires confirmation, removes that home's cards, counter sessions and events, Cycle Time samples, and OEE results, and moves settings that selected it to the first remaining home. It also cleans up legacy unscoped counter sessions linked only to the deleted home's cards while preserving any still referenced by another home. The final home cannot be deleted; a failed save rolls the operation back. Home order is stored independently of the selected profile, and the selection is restored after relaunch; invalid or missing selections are repaired to the first deterministically ordered home. Cards, counter sessions, and saved Cycle Time samples remain scoped to their home. Adding the first counter card creates a production session associated with that home and language-independent tool ID; additional cards reuse it. The counter supports fixed +5/+10 and a validated custom positive-amount Quick Add, all through the same event-backed service. Its confirmed reset appends a zeroing event without erasing history, so Undo can restore the previous count. A session-scoped history screen displays each change with its timestamp, action kind, and balance after the operation. The chronological UTC CSV includes stable event and session IDs, action kind, delta, running balance, and the Undo link; it filters rows to the requested session, escapes CSV delimiters and line breaks, and neutralizes formula-like text fields for spreadsheet apps. Unknown future action-kind identifiers are preserved in CSV; events without a recognized kind fall back to a generic count-change label in the UI. Removing every card keeps the production data available for that home if the tool is added again. Future tools are listed as unavailable until their implementations are added to the registry.

Cycle Time divides total elapsed seconds by produced quantity. Its calculator includes a monotonic stopwatch that can fill the total seconds field; measured values are rounded to the nearest whole second, and manual entry remains available. Takt Time divides net available production seconds, after breaks, by customer demand. Both accept positive whole-number inputs, calculate seconds per unit, work offline, and do not create or mutate production-counter sessions. Cycle Time results can be saved as home-scoped local samples with their input values and timestamp, restored into the calculator, and deleted only after confirmation. The computed result is derived from each saved sample's inputs. Cycle Time history can be filtered to 7, 30, or 90 calendar days or all time; the chart, summary, and list use the same range, while CSV exports the full history as deterministic UTC data scoped to the current home. The user chooses the export destination through Apple's share sheet. Their per-unit math is shared from Foundation-only code outside SwiftUI.

Production Progress is a display-focused companion card for Production Counter. It shows the shared session's produced count, target, remaining count, and completion percentage. It does not change the count; target settings open the same settings used by the counter. It supports medium and large cards and shares the home-scoped Production Counter session regardless of which card is added first.

Defect Counter records defect counts separately from produced units. It uses the shared event-backed counter service for +1, -1, Quick Add, and Undo; its own home-scoped session starts without a production target, and the card supports S/M/L sizes. Defect Rate derives defects divided by produced units from those two home-scoped sessions, updates as either counter changes, and shows a prompt instead of a percentage until production has been recorded. It supports medium and large cards and is included in the Packaging Line starter.

Box Calculator accepts item dimensions and box inner dimensions as positive whole millimeters. It compares all six item orientations and reports the highest capacity for a repeated, uniform orientation, including the item orientation and count along each box axis. It excludes mixed orientations, distinguishes a true no-fit result from a capacity beyond the supported integer range, and explains when the entered dimensions exceed that range. This offline calculator uses medium and large cards and creates no production session.

Unit Converter handles length, mass, volume, and temperature, with metric and selected US customary units. It uses the app's selected locale for number input and output, requires the entire input to parse as a number, allows negative values only for temperature, rejects values below absolute zero, and supports small and medium cards. Its conversion rules are in the SwiftUI-independent `FactoryToolsCore/UnitConversion.swift` file for reuse by future platform targets.

OEE Calculator estimates availability, performance, quality, and overall equipment effectiveness from planned production minutes, unplanned downtime, ideal cycle time, good units, and defective units. It validates whole-number inputs, works offline, and saves home-scoped result snapshots separately from live counter sessions. Saved entries can be loaded back into the calculator or deleted after confirmation. Its history can be filtered to 7, 30, or 90 calendar days, or all time; the summary shows latest, average, best, and change from the previous run, with a time-series chart that scales to values above 100%. History can also be exported as a deterministic CSV with UTC timestamps, stable IDs, inputs, and all four factors; export is limited to the current home and includes all saved results. Performance is left uncapped so values above 100% remain visible for users to investigate, with an in-app note to check the ideal cycle time. The calculator is available as a medium or large home card and its formulas and trend summary math live outside SwiftUI for future platform reuse.

Settings can create a deterministic, versioned JSON snapshot of all local homes, cards, counter sessions and events, processed no-op command receipts, Cycle Time samples, OEE history, and app settings. Version 4 includes canonical counter-command payload signatures on new events and no-op receipts; Version 3 includes no-op command receipts; Version 2 adds OEE history; older Version 1 snapshots remain importable, including counter sessions that predate home/tool assignment. When those legacy sessions are linked to a counter card, import infers the home and tool from that link so the count stays available on the imported home. The snapshot is read-only, uses stable identifiers and sorted records, and is offered through the system share sheet so the user chooses where it goes. It does not send data automatically. Export and import both validate the complete snapshot; export refuses inconsistent local records instead of writing a file that cannot be imported. Validation checks nonblank home names, four-digit-year ISO 8601 timestamp ranges, card/session/home links, Registry-supported card sizes, receipt references and command-ID collisions, known counter action kinds against their deltas and Undo links, verifies reset events zero the running count, and replays each count history, rejecting negative intermediate balances, duplicate event sequences, malformed Undo links, and Undo commands that target an event other than the latest undoable one. Counter commands, Cycle Time samples, and OEE runs apply the same timestamp check before local saves. Unknown future action kinds remain readable through additive import and survive a Version 4 re-export for forward compatibility. Import adds a separate copy with remapped IDs and translated home-name suffixes; current data and language/theme preferences remain in place. A failed save rolls back the added copy. The imported settings record is retained in the file but is not applied over current preferences.

Backup decoding requires the OEE-history field in Version 2 and the command-receipt field in Versions 3 and 4. Version 4 validates each non-null signature's 512-character maximum, schema, operation identifier, and canonical hexadecimal timestamp bits, then checks known operations against the event timestamp, kind, delta, and Undo target. Future operation identifiers remain importable when they use the stable identifier alphabet. Versions 1–3 remain importable without payload signatures; those legacy records keep their prior ID/session replay behavior because their original payload cannot be reconstructed. Version 4 signatures distinguish exact retries from accidental command-ID reuse, including after additive import remaps session IDs. An identifier shared between an event and a receipt is rejected, and a current-version file missing a required section is rejected. Version 1 counter-session ownership inferred from its card link, Version 2 OEE history without command receipts, and Version 3 records without signatures survive import and can be exported again in the current Version 4 format. Imported default-home names are localized to the current app language before the “Imported” suffix is appended.

Backup export and import are capped at 64 MiB and 500,000 total records. Import reads the selected file in bounded chunks and reports a localized message when either limit is exceeded, before decoding or adding records.

History views keep the complete home/session data available and do not discard older records. Cycle Time and OEE derive the selected period's chart and summary values once per view update; latest/previous, average, and best summary values are found in one pass. Counter, Cycle Time, and OEE CSV files snapshot Sendable values for the share sheet and format the full CSV only when the system requests the file.
