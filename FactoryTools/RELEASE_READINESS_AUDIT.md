## Release preflight evidence

The normal static command passes. `python Scripts/validate_static.py --release-preflight` uses the selected Japan (JP), JPY ¥980 base-storefront candidates by default and reports five project identity/configuration blockers below. That count is only the source-configurable subset; it is not the count of all release gates and a passing result is not release approval. Apple enrollment, App Store Connect setup, native builds/tests, URL reachability, review assets, and publication are outside this command. The storefront values are syntax-checked only; they do not configure App Store Connect. Use `--candidate-base-storefront` and `--candidate-base-storefront-price` to check an alternative, but still verify the actual territory, price, and signed purchase sheet in App Store Connect. Apple's official Japan pricing guidance also explicitly uses ¥980 as an example custom storefront price. Family Sharing is decided off and must be verified in App Store Connect; it is no longer an unresolved product decision.

1. Debug development Bundle ID.
2. Release development Bundle ID.
3. Apple Developer Team ID.
4. Public HTTPS privacy-policy URL.
5. Public HTTPS support URL.
The selected product ID candidate is `factorytools.pro.lifetime`.
Candidate preflight values validate syntax only; they do not modify Xcode settings, create an App Store Connect product, establish ownership, configure signing, select a valid territory/currency combination, or prove URL reachability.
The preflight's five source-checkable blocker count covers the app Bundle ID in Debug and Release, Team ID, privacy URL, and support URL when the base storefront candidates and product ID are set. It does not count or verify Apple Developer Program enrollment, Paid Apps Agreement, tax/banking setup, IAP tax category, native/device verification, store screenshots, the App Store Connect Family Sharing switch, or completed questionnaires; those are listed in the required-gates table above.

## Release decision rule

Do not label the app ready for distribution until every required-build gate above has direct evidence from a signed Apple-platform archive and App Store Connect configuration. Keep the current Windows validation result labeled as source-level verification.
